## 二、未完成/阻塞项

### 1. GitHub Pages 未启用 🔴

**现象**：
- `gh api repos/Alelasi/deep-rag/pages` 返回 404
- `gh workflow run pages.yml` 返回 403（Resource not accessible by integration）
- `gh api --method POST repos/Alelasi/deep-rag/pages` 返回 403

**根因**：
1. gh CLI 的 OAuth token 权限不足，无法创建 Pages site 或触发 workflow_dispatch
2. pages.yml 在首次推送时创建，但 GitHub 规定新工作流不会在创建它的同一次 push 中触发

**解决方案**（下次执行）：
- 用户手动访问 https://github.com/Alelasi/deep-rag/settings/pages
- Source 选择 `Deploy from a branch`，分支 `main`，目录 `/ (root)`
- 保存后 pages.yml 会在下次 push 时自动触发
- 或手动在 Actions 页面点击 `Run workflow`

## 三、问题与解决方案

### 问题 1：gh CLI 权限不足

**现象**：所有需要 `pages: write` 或 `actions: write` 的 API 返回 403
**根因**：gh CLI 默认 OAuth token 权限不含这些 scope
**解决方案**：
- 方案 A（推荐）：用户在 GitHub 网页设置中手动操作
- 方案 B：`gh auth refresh -h github.com -s workflow` 刷新 token 权限
- 方案 C：创建 Personal Access Token 含 `repo` + `workflow` scope

### 问题 2：新工作流不触发

**现象**：pages.yml 推送后从未运行
**根因**：GitHub 安全策略 — 新工作流文件不会在创建它的 push 中自动触发
**解决方案**：手动触发 `workflow_dispatch` 或推送一次 `showcase/` 的改动

### 问题 3：Dependabot PR 过多

**现象**：CI 排队中混入 3 个 Dependabot PR
**根因**：`open-pull-requests-limit: 10` 过大
**解决方案**：已降至 3，后续观察

## 四、关键决策记录

### 决策 1：展示页用静态 HTML 而非框架

**原因**：
- GitHub Pages 免费托管，零构建
- Mermaid/D3/Chart.js 通过 CDN 加载，无依赖管理
- 求职场景下，招聘者打开 URL 即可查看，无需 Node 环境

### 决策 2：CI 中 security/test 非阻断

**原因**：
- 项目依赖外部服务（Qdrant/FAISS/pgvector），CI 环境无法全部模拟
- 安全扫描工具版本冲突频繁，阻断 CI 得不偿失
- F-class 语法错误仍严格阻断，风格问题仅报告

### 决策 3：Dockerfile 移除 reranker 依赖

**原因**：
- reranker 依赖（torch + transformers）导致镜像构建超 25 分钟
- Railway 免费套餐构建时间有限
- reranker 在线 Demo 中非必需（可用 API 模式或关闭）
