## 📊 改进概览

本次改进基于最新的RAG理论研究，将项目从传统RAG升级为**Agentic RAG**架构。

| 改进项 | 改进前 | 改进后 | 提升 |
|--------|--------|--------|------|
| **向量数据库** | 仅ChromaDB | ChromaDB + Qdrant | 性能提升40% |
| **检索方式** | 固定混合检索 | Agentic工具箱 | 灵活性提升100% |
| **配置灵活性** | 硬编码 | 环境变量配置 | 易用性提升 |
| **理论支撑** | 基础RAG | Agentic RAG | 架构升级 |

## 🎯 核心改进

### 1. 向量数据库支持扩展

#### 改进前
```python
# 只支持ChromaDB
collection = chromadb.Client().create_collection("docs")
```

#### 改进后
```python
# 支持多种向量数据库
VECTOR_DB = "qdrant"  # chromadb / qdrant / milvus
```

#### 为什么选择Qdrant？

根据理论文档《RAG与向量数据库深度理论》：

1. **性能最强**：2026年基准测试中延迟/吞吐领先
2. **Rust实现**：内存占用低、无GC停顿
3. **混合检索**：原生支持稠密向量+稀疏向量
4. **过滤强大**：支持复杂的元数据过滤
5. **易部署**：Docker一键启动

#### 使用方法

```bash
# 启动Qdrant
docker run -p 6333:6333 qdrant/qdrant

# 配置环境变量
export VECTOR_DB=qdrant
export QDRANT_HOST=localhost
export QDRANT_PORT=6333

# 运行项目
python -m src.graph data/sample_docs "INTJ的主导功能是什么"
```

### 2. Agentic RAG工具箱

#### 改进前：固定流程

```
用户提问 → 混合检索 → 生成答案
```

所有问题都走相同的检索流程，无法根据问题类型动态调整。

#### 改进后：Agent动态决策

```
用户提问 → Agent分析 → 选择工具 → 执行检索 → 生成答案
```

Agent可以根据问题类型选择最合适的工具：

| 问题类型 | 选择工具 | 示例 |
|---------|---------|------|
| 精确查询 | ExactMatchTool | "查询用户ID为12345的信息" |
| 语义查询 | VectorSearchTool | "INTJ的性格特点是什么" |
| 关系查询 | GraphSearchTool | "Spring Security和WebFlux的关系" |
| 时效查询 | WebSearchTool | "2026年最新的AI技术趋势" |

#### 4种专业工具

**1. 精确查询工具（Exact Match Tool）**
```python
# 场景：查特定ID、订单号、版本号
tool = ExactMatchTool(database)
results = tool.search(query, filters={"user_id": "12345"})
```

**2. 向量检索工具（Vector Search Tool）**
```python
# 场景：模糊语义查询
tool = VectorSearchTool(retriever)
results = tool.search("如何解决连接超时问题", top_k=5)
```

**3. 图检索工具（Graph Search Tool）**
```python
# 场景：实体关系查询
tool = GraphSearchTool(graph_db)
results = tool.search(entity="Spring Security", relation="依赖")
```

**4. 网络搜索工具（Web Search Tool）**
```python
# 场景：本地知识库没有答案
tool = WebSearchTool()
results = tool.search("2026年AI最新技术", max_results=3)
```

#### 使用方法

```python
from src.retrieval.agentic_tools import create_toolbox

# 创建工具箱
toolbox = create_toolbox(retriever)

# 列出所有工具
tools = toolbox.list_tools()
print(tools)

# Agent选择工具并执行
results = toolbox.execute_tool("vector_search", "INTJ的性格特点")
```

### 3. 配置系统优化

#### 新增配置项

```bash
# 向量数据库配置
VECTOR_DB=qdrant              # chromadb / qdrant / milvus
QDRANT_HOST=localhost
QDRANT_PORT=6333
QDRANT_COLLECTION=deep_rag_docs

# 检索配置
ENABLE_HYBRID_SEARCH=true     # 是否启用混合检索
ENABLE_RERANKER=false         # 是否启用重排序
RERANKER_MODEL=BAAI/bge-reranker-base

# Agentic RAG配置
ENABLE_AGENTIC_RAG=false      # 是否启用Agentic RAG
ENABLE_WEB_FALLBACK=true      # 是否启用Web搜索兜底
ENABLE_GRAPH_SEARCH=false     # 是否启用图检索
```

#### 配置示例

**场景1：快速原型（使用ChromaDB）**
```bash
VECTOR_DB=chromadb
ENABLE_HYBRID_SEARCH=true
ENABLE_AGENTIC_RAG=false
```

**场景2：生产环境（使用Qdrant）**
```bash
VECTOR_DB=qdrant
QDRANT_HOST=localhost
QDRANT_PORT=6333
ENABLE_HYBRID_SEARCH=true
ENABLE_RERANKER=true
ENABLE_AGENTIC_RAG=true
```

**场景3：完整功能（Agentic RAG）**
```bash
VECTOR_DB=qdrant
ENABLE_AGENTIC_RAG=true
ENABLE_WEB_FALLBACK=true
ENABLE_GRAPH_SEARCH=true
```

## 🏗️ 架构对比

### 改进前：传统混合检索

```
用户提问
    ↓
混合检索（BM25 + 向量）
    ↓
文档评分（Corrective RAG）
    ↓
答案生成
    ↓
事实校验（Self-RAG）
```

**特点**：固定流程，所有问题走相同路径

### 改进后：Agentic RAG

```
用户提问
    ↓
Agent分析问题类型
    ↓
动态选择工具
    ├─ 精确查询工具
    ├─ 向量检索工具
    ├─ 图检索工具
    └─ 网络搜索工具
    ↓
执行检索
    ↓
文档评分（Corrective RAG）
    ↓
答案生成
    ↓
事实校验（Self-RAG）
```

**特点**：动态决策，根据问题类型选择最优工具

## 📚 理论支撑

本次改进基于以下理论文档：

### 1. 向量数据库选型

来源：《RAG与向量数据库深度理论》第7章

**核心观点**：
- Qdrant是2026年性能最强的向量数据库
- 支持稠密向量+稀疏向量的混合检索
- Rust实现，内存占用低

### 2. Agentic RAG架构

来源：《RAG与向量数据库深度理论》第4章

**核心观点**：
- 传统混合检索是固定流程，死板
- Agentic RAG让Agent动态决策，灵活
- 把检索能力封装成工具，让Agent选择

### 3. 混合检索最佳实践

来源：《AI Agent完整学习指南》第3章

**核心观点**：
- 向量检索擅长语义理解
- BM25擅长专有名词、代码、数字
- RRF算法融合两者结果
