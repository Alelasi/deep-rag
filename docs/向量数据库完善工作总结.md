### 2. pgvector 技术深度

**索引优化**：
```sql
CREATE INDEX documents_embedding_idx
ON documents
USING hnsw (embedding vector_cosine_ops);
```

**HNSW 算法**：
- 时间复杂度：O(log N)
- 召回率：95%+
- 性能提升：100倍+

**距离度量**：
- Cosine Distance（`<=>`）- 语义相似
- L2 Distance（`<->`）- 欧氏距离
- Inner Product（`<#>`）- 点积

### Q2：为什么选择 pgvector？

**回答**：
> pgvector 的优势在于：
> 1. **企业级稳定性** - 基于 PostgreSQL，久经考验
> 2. **事务支持** - ACID保证数据一致性
> 3. **SQL生态** - 可以用SQL做复杂查询和JOIN
> 4. **运维成熟** - 备份、监控、高可用方案完善
> 5. **成本优化** - 与现有PostgreSQL数据库共用，无需额外部署
>
> 我实现了完整的 pgvector 集成，包括：
> - HNSW索引加速
> - 3种距离度量（Cosine/L2/Inner Product）
> - 元数据过滤
> - 批量写入优化
> - 12个单元测试覆盖

---

### Q3：pgvector 如何优化检索性能？

**回答**：
> 我使用了 **HNSW索引**（Hierarchical Navigable Small World）：
> ```sql
> CREATE INDEX documents_embedding_idx
> ON documents
> USING hnsw (embedding vector_cosine_ops);
> ```
>
> HNSW 是一种图索引算法：
> - **时间复杂度**：O(log N)
> - **召回率**：95%+
> - **适用场景**：百万级向量检索
>
> 相比暴力搜索（O(N)），性能提升 **100倍以上**。
>
> 此外，我还实现了：
> - **批量写入优化**：使用 `execute_values` 批量插入
> - **连接池管理**：复用数据库连接
> - **元数据索引**：JSONB字段索引加速过滤
