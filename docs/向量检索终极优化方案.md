### 1. Hybrid Search（混合搜索）⭐ 最有效

**核心思想**：BM25（关键词）+ Vector（语义）双路召回 + RRF 融合

#### 原理

```
查询："深度学习模型优化"
    ↓
并行执行：
├─ BM25 搜索 → ["深度学习", "模型", "优化"] → 召回 100 个
└─ Vector 搜索 → embedding(query) → 召回 100 个
    ↓
RRF 融合 → 合并去重 → 重排序 → top-10
```

#### 实现

```python
class HybridRetriever:
    """混合检索器（BM25 + Vector + RRF）"""
    
    def retrieve(self, query: str, top_k: int = 10):
        # 1. 并行执行两路搜索
        bm25_results = self.bm25_search(query, k=100)
        vector_results = self.vector_search(query, k=100)
        
        # 2. RRF 融合（k=60 是最佳实践）
        k = 60
        rrf_scores = {}
        
        for rank, doc in enumerate(bm25_results):
            doc_id = doc["id"]
            rrf_scores[doc_id] = rrf_scores.get(doc_id, 0) + 1 / (k + rank + 1)
        
        for rank, doc in enumerate(vector_results):
            doc_id = doc["id"]
            rrf_scores[doc_id] = rrf_scores.get(doc_id, 0) + 1 / (k + rank + 1)
        
        # 3. 按 RRF 分数排序
        sorted_ids = sorted(rrf_scores.keys(), key=lambda x: -rrf_scores[x])
        return sorted_ids[:top_k]
```

#### 性能数据

| 指标 | 单路（Vector） | 混合（BM25+Vector） | 提升 |
|------|---------------|-------------------|------|
| 召回率 @10 | 65-78% | **91%** | +13-26% |
| 延迟 | 10ms | **16ms** | +6ms（可接受）|
| 适用场景 | 语义搜索 | **通用搜索** | 全场景 |

**关键发现**：
- RRF 融合只增加 **6ms** 延迟（相比 LLM 推理 500-2000ms 可忽略）
- 召回率提升 **13-26%**（从 65-78% → 91%）
- k=60 是跨领域最佳参数

### 2. Query Expansion（查询扩展）🆕 LLM 驱动

**核心思想**：用 LLM 生成多个查询变体，增加召回覆盖面

#### 原理

```
原始查询："如何优化 RAG 系统？"
    ↓
LLM 扩展 → 生成 3-5 个变体：
├─ "RAG 系统性能优化方法"
├─ "检索增强生成优化技巧"
├─ "向量检索召回率提升"
└─ "RAG pipeline 加速策略"
    ↓
并行搜索 → 合并结果 → 去重 → top-10
```

#### 实现

```python
class QueryExpander:
    """LLM 驱动的查询扩展"""
    
    def __init__(self, llm):
        self.llm = llm
    
    def expand(self, query: str, num_variants: int = 3) -> list[str]:
        """生成查询变体"""
        prompt = f"""
        原始查询：{query}
        
        生成 {num_variants} 个语义相似但表达不同的查询变体。
        要求：
        1. 保持原意
        2. 使用不同词汇
        3. 覆盖不同角度
        
        输出格式（每行一个）：
        """
        
        response = self.llm.generate(prompt)
        variants = [line.strip() for line in response.split('\n') if line.strip()]
        
        return [query] + variants[:num_variants]
    
    def retrieve_with_expansion(self, query: str, retriever, top_k: int = 10):
        """扩展查询 + 多路检索 + 合并"""
        # 1. 生成查询变体
        queries = self.expand(query, num_variants=3)
        
        # 2. 并行检索
        all_results = []
        for q in queries:
            results = retriever.search(q, k=top_k * 2)
            all_results.extend(results)
        
        # 3. 去重 + 重排
        seen = set()
        unique_results = []
        for doc in all_results:
            if doc["id"] not in seen:
                seen.add(doc["id"])
                unique_results.append(doc)
        
        return unique_results[:top_k]
```

#### 性能数据

| 指标 | 单查询 | 查询扩展（3变体） | 提升 |
|------|--------|-----------------|------|
| 召回率 @10 | 78% | **89%** | +11% |
| 延迟 | 10ms | **35ms** | +25ms |
| 适用场景 | 精确查询 | **模糊查询** | 歧义消除 |

**优化技巧**：
- 用小模型生成变体（Llama 3.2 1B，延迟 <20ms）
- 缓存常见查询的扩展结果
- 只在召回率低时触发扩展

**参考**：
- [LLM-Assisted Pseudo-Relevance Feedback](https://arxiv.org/abs/2601.11238)
- [Query Expansion by Prompting LLMs](https://arxiv.org/abs/2305.03653)

### 3. Two-Stage Reranking（两阶段重排）⭐ 准确率之王

**核心思想**：粗筛（快速） + 精排（准确）

#### 原理

```
查询 → 第一阶段：向量检索（快速召回 top-100）
           ↓
       第二阶段：CrossEncoder 重排（精确排序 top-10）
```

#### 实现

```python
class TwoStageRetriever:
    """两阶段检索器"""
    
    def __init__(self, vector_index, cross_encoder):
        self.vector_index = vector_index
        self.cross_encoder = cross_encoder
    
    def retrieve(self, query: str, k: int = 10, recall_k: int = 100):
        """两阶段检索"""
        # 阶段1：向量检索（快速召回）
        candidates = self.vector_index.search(query, k=recall_k)
        
        # 阶段2：CrossEncoder 重排（精确排序）
        pairs = [(query, doc["content"]) for doc in candidates]
        scores = self.cross_encoder.predict(pairs)
        
        # 排序
        ranked_idx = np.argsort(scores)[::-1][:k]
        return [candidates[i] for i in ranked_idx]
```

#### CrossEncoder vs Bi-Encoder

| 模型 | 原理 | 速度 | 准确率 |
|------|------|------|--------|
| **Bi-Encoder** | 分别编码 query 和 doc | 快（可预计算） | 中等 |
| **CrossEncoder** | 联合编码 [query, doc] | 慢（实时计算） | **最高** |

#### 性能数据

| 指标 | 单阶段（Vector） | 两阶段（Vector+CrossEncoder） | 提升 |
|------|-----------------|----------------------------|------|
| 召回率 @10 | 85% | **96-98%** | +11-13% |
| 延迟 | 2ms | **15-25ms** | +13-23ms |
| 适用场景 | 速度优先 | **准确率优先** | 金融/医疗 |

**优化技巧**：
- 用小 CrossEncoder（MiniLM，延迟 <10ms）
- 只对 top-50 重排（而非 top-100）
- GPU 批量推理（10x 加速）

**参考**：
- [Scaling Laws for Cross-Encoder Reranking](https://arxiv.org/abs/2603.04816)
- [Distilling LLMs into Cross-Encoders](https://arxiv.org/abs/2405.07920)

### 4. ColBERT Late Interaction（晚期交互）🆕 平衡之选

**核心思想**：Token 级别的细粒度匹配

#### 原理

```
Query: "深度学习"
  ↓ 编码为多个 token embeddings
  [深, 度, 学, 习] → [v1, v2, v3, v4]

Document: "深度学习是机器学习的分支"
  ↓ 编码为多个 token embeddings
  [深, 度, 学, 习, 是, ...] → [d1, d2, d3, d4, d5, ...]

相似度 = MaxSim(v1, [d1...dn]) + MaxSim(v2, [d1...dn]) + ...
```

#### 实现

```python
from fastembed import LateInteractionTextEmbedding

class ColBERTRetriever:
    """ColBERT 晚期交互检索器"""
    
    def __init__(self):
        self.model = LateInteractionTextEmbedding("colbert-ir/colbertv2.0")
    
    def encode_query(self, query: str):
        """编码查询为多向量"""
        return self.model.query_embed(query)
    
    def encode_documents(self, docs: list[str]):
        """编码文档为多向量"""
        return self.model.passage_embed(docs)
    
    def compute_score(self, query_vecs, doc_vecs):
        """计算 MaxSim 分数"""
        # query_vecs: (num_query_tokens, dim)
        # doc_vecs: (num_doc_tokens, dim)
        
        # 计算所有 token 对的相似度
        sim_matrix = np.dot(query_vecs, doc_vecs.T)  # (Q, D)
        
        # 对每个 query token，取最大相似度
        max_sims = sim_matrix.max(axis=1)  # (Q,)
        
        # 求和
        score = max_sims.sum()
        
        return score
```

| 存储 | 1x | **3-5x** | 1x |
| 适用场景 | 速度优先 | **平衡** | 准确率优先 |

**优势**：
- 比 Bi-Encoder 准确（+7%）

### 5. Adaptive Retrieval（自适应检索）🆕 智能路由

**核心思想**：根据查询难度选择检索策略

#### 原理

```
查询 → 难度评估
    ↓
简单查询（"什么是 Python"）
    → 单路 Vector 检索（快速）
    
中等查询（"如何优化 RAG"）
    → Hybrid 检索（BM25 + Vector）
    
困难查询（"对比 HNSW 和 IVF 的适用场景"）
    → Hybrid + Query Expansion + Reranking（准确）
```

#### 实现

```python
class AdaptiveRetriever:
    """自适应检索器"""
    
    def __init__(self, vector_retriever, hybrid_retriever, reranker):
        self.vector_retriever = vector_retriever
        self.hybrid_retriever = hybrid_retriever
        self.reranker = reranker
    
    def estimate_difficulty(self, query: str) -> str:
        """评估查询难度"""
        # 简单规则
        if len(query.split()) <= 3:
            return "easy"
        elif "对比" in query or "区别" in query or "如何" in query:
            return "hard"
        else:
            return "medium"
    
    def retrieve(self, query: str, k: int = 10):
        """自适应检索"""
        difficulty = self.estimate_difficulty(query)
        
        if difficulty == "easy":
            # 简单查询：单路 Vector
            return self.vector_retriever.search(query, k=k)
        
        elif difficulty == "medium":
            # 中等查询：Hybrid
            return self.hybrid_retriever.retrieve(query, k=k)
        
        else:  # hard
            # 困难查询：Hybrid + Reranking
            candidates = self.hybrid_retriever.retrieve(query, k=k*10)
            return self.reranker.rerank(query, candidates, k=k)
```

#### 性能数据

| 查询类型 | 占比 | 策略 | 平均延迟 | 召回率 |
|---------|------|------|---------|--------|
| 简单 | 40% | Vector | 2ms | 90% |
| 中等 | 40% | Hybrid | 16ms | 93% |
| 困难 | 20% | Hybrid+Rerank | 30ms | 97% |
| **加权平均** | 100% | **自适应** | **12ms** | **93%** |

**优势**：
- 平衡速度和准确率
- 节省计算资源（40% 查询用快速路径）
- 提升用户体验（简单查询秒回）

### 6. GPU Batch Processing（GPU 批量处理）⚡ 吞吐之王

**核心思想**：批量处理 + GPU 并行

#### 实现

```python
class GPUBatchRetriever:
    """GPU 批量检索器"""
    
    def __init__(self, index_gpu, batch_size=128):
        self.index_gpu = index_gpu
        self.batch_size = batch_size
    
    def batch_search(self, queries: list[str], k: int = 10):
        """批量搜索"""
        # 1. 批量编码查询
        query_embeddings = self.encode_batch(queries)
        
        # 2. GPU 批量搜索
        distances, ids = self.index_gpu.search(query_embeddings, k)
        
        return distances, ids
    
    def encode_batch(self, texts: list[str]):
        """批量编码（GPU 加速）"""
        from sentence_transformers import SentenceTransformer
        
        model = SentenceTransformer('BAAI/bge-small-zh-v1.5', device='cuda')
        embeddings = model.encode(
            texts,
            batch_size=self.batch_size,
            show_progress_bar=False,
            convert_to_numpy=True
        )
        
        return embeddings
```

#### 性能数据

| 方式 | 延迟（单条） | 吞吐（QPS） | 提升 |
|------|------------|-----------|------|
| CPU 单条 | 10ms | 100 | 1x |
| CPU 批量 | 5ms | 200 | 2x |
| GPU 单条 | 3ms | 333 | 3.3x |
| **GPU 批量** | **1ms** | **10,000+** | **100x** |

**优化技巧**：
- 批量大小：32-128（根据 GPU 显存）
- 异步处理：用队列缓冲请求
- 混合精度：FP16（2x 加速）
