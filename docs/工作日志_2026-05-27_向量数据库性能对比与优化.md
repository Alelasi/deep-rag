## 🐛 遇到的问题与解决方案

### 问题 1：GPU 利用率低（尖刺）

**现象**：
- GPU 3D 利用率只有 2-7%
- 专用 GPU 内存持续使用（4.5GB）
- 写入速度慢

**根本原因**：
- ChromaDB 写入太慢，成为瓶颈
- GPU 向量化很快（几毫秒），但等待数据库写入完成才能处理下一个批次

**解决方案**：
1. 尝试 4 线程版本（2读取 + 1GPU + 1写入）→ 效果不明显
2. 测试不同向量数据库性能 → 发现 LanceDB 快 30x
3. 迁移到 LanceDB → 问题解决

---

### 问题 2：ChromaDB 一次性获取 15 万文档超限

**现象**：
```
chromadb.errors.InternalError: Error executing plan: Internal error: error returned from database: (code: 1) too many SQL variables
```

**原因**：
- ChromaDB 基于 SQLite
- 一次性获取 15 万文档超过 SQL 变量限制

**解决方案**：
- 分批获取（每批 1000 个）
- 或直接迁移到 LanceDB（支持大规模数据）

---

### 问题 3：pgvector 扩展未启用

**现象**：
```
vector type not found in the database
```

**原因**：
- PostgreSQL 容器启动后，pgvector 扩展未自动启用

**解决方案**：
```python
import psycopg2
conn = psycopg2.connect(host='localhost', database='postgres', user='postgres', password='postgres')
cur = conn.cursor()
cur.execute('CREATE EXTENSION IF NOT EXISTS vector')
conn.commit()
```

### 问题 4：Python 脚本 GBK 编码错误

**现象**：
```
UnicodeDecodeError: 'gbk' codec can't decode byte 0x9a in position 55
```

**原因**：
- Windows 默认使用 GBK 编码
- 脚本包含中文注释，保存为 UTF-8

**解决方案**：
```python
with open('script.py', 'r', encoding='utf-8') as f:
    exec(f.read())
```

## 💡 经验总结

### 1. 向量数据库选型原则：

- **小规模（<10万）**：ChromaDB（简单易用）
- **中规模（10-100万）**：LanceDB（快速 + 持久化）
- **大规模（>100万）**：Milvus（亿级规模 + GPU 加速）
- **已有 PostgreSQL**：pgvector（与业务数据无缝结合）
- **极致性能**：Qdrant（高性能 Hybrid RAG）

### 2. 性能优化策略：

- **热数据缓存**：FAISS 内存索引（极速）
- **分层存储**：热数据（FAISS）+ 温数据（LanceDB）
- **批量写入**：减少数据库 I/O 次数
- **GPU 加速**：向量化阶段使用 GPU

### 3. 数据库迁移注意事项：

- **分批迁移**：避免一次性加载过多数据
- **验证完整性**：迁移后检查文档数量
- **保留备份**：迁移前备份原数据库
